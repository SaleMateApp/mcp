# Video model choice

1. If the user has not chosen a video model, call `list_models` with a `recommendation` describing their `use_case`, stated `budget_credits`, duration, format and supplied reference counts. Use `single_video` for one clip; use the relevant workflow goal for a product ad, episode or motion transfer. Explain the returned recommendation and alternative, why they fit, their tradeoffs, missing inputs and indicative prices; then ask which video model or workflow the user wants. Never silently choose Vanta or substitute another model after a failure. If the user already named a model, preserve it with `preferred_model`; an exclusion or mismatch requires a new user choice, never an automatic fallback.
2. Direct `generate_video` choices are Vanta (`vanta`), Wan 3.0 (`wan-3.0`), HappyHorse (`happyhorse`), Nova (`nova`), Seedance 2.0 Core (`seedance-2.0-mini`), Seedance 2.0 Fast (`seedance-2.0-fast`), Seedance 2.0 (`seedance-2.0`), Veo 3.1 Lite/Fast (`veo3.1-lite`, `veo3.1-fast`), and Omni Flash (`omni-flash`). Veo 3.1 Quality (`veo3.1-quality`) is excluded from new MCP requests. Lite (`video-lite`), Pro (`video-pro`) and Pro 1.5 (`video-pro-1.5`) are excluded only from standalone `generate_video`; Veo 3.1 Lite remains offered. Default and Sparrow retain their separate workflow model choices, including Default Lite/Pro/Pro 1.5 and Sparrow Seedance 1.5 Pro. Vibe Shift is a separate motion-transfer tool. Do not offer Beat Cut or Sora through these tools.
3. Collect the selected model's supported duration, resolution and media. Keep the complete reference list within 32 MiB, including the main reference; per-file limits still apply. Vanta starts at five seconds. Flow models use `provider-default` output dimensions; do not promise selectable 1080p or 4K. Seedance supports text, ordered image/video references with prompt aliases, or exactly two first/last-frame images; no audio references. Wan requires explicit roles for video/audio references and a measured native quote. Wan does not accept WebM or Ogg through this adapter.
4. After the user chooses, call `estimate_cost` for that tool's exact inputs. State the price and supply the user's `max_credits` ceiling. Recommendation prices are indicative base prices, not a personalized quote or spending permission. Do not quote every candidate to rank them: some estimates upload or measure references. Follow `estimate-then-approve` when confirmation is required. The human approves; never call approval on their behalf or change inputs after approval.
5. Once a `job_id` is returned, check progress with `get_job` or bounded `wait_for_job`, not another `generate_video` call. Preserve the returned backend. Respect `retry_after_seconds`.

For example, `list_models({kind:"video", recommendation:{use_case:"single_video", budget_credits:30, duration_seconds:8, reference_images:1, aspect_ratio:"9:16", priority:"lowest_cost"}})` asks for a free shortlist using one supplied image. Omitted reference counts mean none supplied. Recommendations may include a related workflow outside the `kind` filter when the use case calls for one. Input templates contain no uploaded asset IDs or spending approval: fill missing inputs only after the user chooses.

Use capabilities, not guesses about names: "Fast" does not prove lower latency, and backend health does not prove generation reliability. Do not claim a model is best for realism, dialogue or quality without comparison evidence. If nothing fits, explain the reason and ask before changing duration, format, budget, input type or the requested model. Never present an unknown measured price as within budget.

For dialogue, product fidelity or cinematic goals, pass `quality_focus` (`dialogue`, `product_fidelity` or `cinematic`) and the user's stated `dialogue_language` when known. Explain returned `quality_evidence` with its sample size, test date, actual settings and limitations. A single ASR result reports script recovery, not human pronunciation, lip sync or visual quality. English evidence does not establish another language's performance. Current saved observations do not establish a comparative winner and do not change capability/budget ordering. Missing evidence means unknown, not worse: do not downgrade Seedance or another unreviewed model. Never generalize a direct-video result to Narrative, Mini Dramas, another provider route or another model version. If the response says `insufficient_comparative_evidence`, say that plainly; do not generate a new paid comparison without the user's request.

A timeout, missing lookup or `unknown` response does not authorize another generation. Reconcile only by replaying unchanged inputs; keep all IDs and the ceiling unchanged. Never use a new ID to escape uncertainty. An intentional additional result uses `new_take: true` and a fresh `take_id`, which stays unchanged on its retries.

Only offer `cancel_job` where the catalog supports it: Vanta and Wan before execution, legacy Jobs under its native rules. Nova, HappyHorse, Flow and Seedance have no safe MCP cancellation. Never promise a refund before returned billing confirms it. A finished provider task is not a successful user output until the MCP reports durable output and settled billing.
